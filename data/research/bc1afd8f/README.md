# `data/research/bc1afd8f/` — session arena-bc1afd8f evidence index

Read-only evidence for one question set: *does every listed Hotspawn CS2 fixture have a
sourced pick, can the site actually be published fresh, and can a phone reader find the
picks?* Every file here is generated by a module in `scripts/bc1afd8f_*.py`; no number in
them was typed by hand, and none of them changes a probability, a pick, an alias or a price.

## Corrections and supersessions

* **`live-coverage-20261022T091704Z.json` mislabels research-model rows as money lines.** Its
  `classify()` accepted "has quote records" as "has a betting line", and a research-model row
  carries quote records too (fixture `1082926`'s quote provider is `HLTV world ranking`, not a
  book). The `money-line` / `model-only` split in that file is therefore wrong — its
  `active_with_pick`, `active_blank` and per-fixture probabilities are not. Classification now
  reads the row's own `method` only, is pinned by `ModelRowClassificationTests`, and the file
  `live-coverage.json` supersedes it.
* **`challenge` was over-reported in the same file.** A word such as `captcha` also occurs inside
  ordinary bundled JavaScript, so a 2.5 MB successful Bovada response and a 3 MB Polymarket
  directory were both flagged as challenge pages. A marker now only counts when the response also
  failed or is smaller than 20 kB, and the markers actually found are published beside it.
* The first live run's stable-named reports were overwritten by the workflow's own
  `git checkout -- data/` restore (run 39753692322); the restore now excludes this directory.
* `gate-fresh-snapshot.md` measures the suite against a snapshot collected **before** main's PR #179
  fix existed on this branch, so its 15 failures + 19 errors include the tie-break assertion that
  main has since fixed. The newest runner run reports both the build outcome and a fresh gate
  measurement over the merged code; read `build-outcome.json` and the newest dated files together.

## What this evidence is used for

* `.github/workflows/pages-artifact-guard.yml` — re-deploys the newest verified Pages artifact
  whenever the public site is not serving it, in a concurrency group that pushes to `main` cannot
  starve, and dispatches `pages.yml` when the newest verified snapshot passes the brief's
  eight-hour bound. It commits nothing, because `root-publish-risk.md` shows that committing a
  fresh snapshot over the frozen `data/evidence/` tree breaks the build every pull request runs.
* `tests/test_bc1afd8f.py::EvenTieBreakValidationTests` — pins the live row shape that stopped
  the 09:15:53Z snapshot from building at all, against the tie-break replay now on `main`.
